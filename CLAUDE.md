# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start the Vite dev server
- `npm run build` — production build
- `npm run preview` — preview a production build locally

There is no lint or test setup in this repo (no test framework, no ESLint config).

## Architecture

This is a small single-page React app ("AUTOPIR", formerly "Ruta PIR"; repo/package name academia-pir), built with Vite, backed by Supabase.

- Entry chain: `index.html` → `src/main.jsx` → `src/App.jsx`. `src/App.jsx` is the entire application (~2000 lines): all components, view logic, and Supabase calls live in this one file, organized as several feature components rendered by a top-level `AcademiaPIR` component based on a `section` state variable (tab navigation).
- Sections/tabs (`section` state, set via the nav in `AcademiaPIR`, in this order): `simulacros` (self-test quizzes), `banco` (question bank — "Reales" curated + "Inventadas por IA" AI-generated, open to all users with a daily quota, save-to-bank admin-only; no course/subject filter — real questions barely have a meaningful `curso` grouping — just a free-text search box that filters the current tab's questions by substring match against the question/options/explanation/tema), `duelo` (1v1 duel/battle mode), `ranking` (leaderboard + streaks), `flashcards` (second-to-last tab: spaced-repetition flashcards, Anki-style, front/back cards seeded from an imported Anki deck — see `flashcards`/`flashcards_progreso` below), `perfil` (last tab: daily wheel/"ruleta", fail history, favorites — kept deliberately light). `Logros` (level/badge grid + streak & accuracy stats) is not a nav tab: it lives behind a small award-icon button in the header, next to the gear/Ajustes icon, opening as an anchored dropdown (`Header`'s `mostrarLogros` state renders `<Logros compact />`) rather than taking a full tab slot. There is no `temario` tab — `TEMARIO` (static data in `src/temario.js`) is still imported and used internally to ground AI question generation (`GenerarPreguntasIA`), just not shown as a readable tab. There used to be a `curiosidades` tab (AI-generated trivia in that same nav slot, via `api/generar-curiosidades.js`); it was replaced outright by `flashcards` per user request — the `curiosidades`/`curiosidades_vistas` tables and `supabase-curiosidades.sql` are dead but left in Supabase/the repo as history, nothing in `App.jsx` references them anymore.
- The `curso` column on `preguntas` is a free-text field, not a fixed taxonomy — for a chunk of imported real questions it actually holds an exam/simulacro label (e.g. "Simulacro 01 (AMIR)") rather than a subject name; those get renamed to their real "PIR YY" edition label via one-off `update` statements in `supabase-*.sql` files as the user requests each renaming (see `supabase-rename-simulacros.sql` for the pattern: a regex anchored on the simulacro number to avoid collisions like "1" matching "10").
- `Flashcards`: front/back cards (`flashcards.frontal`/`.posterior`, grouped by `mazo`) reviewed with a simplified SM-2 spaced-repetition algorithm (`calcularSM2` in `App.jsx`, same model Anki uses) — a card is "due" when `flashcards_progreso.proxima_revision` is null or `<=` today. Each review ends with one of 4 difficulty ratings (Muy difícil/Difícil/Fácil/Muy fácil, mapped to SM-2 quality 0/3/4/5) which updates that user's `ease_factor`, `intervalo_dias`, `repeticiones` and `proxima_revision` for that card via `registrarRepasoFlashcard`. A session pulls up to `TAM_SESION_FLASHCARDS` (20) due cards at random; the deck data itself (271 cards from a "Mi baraja" Anki export, tagged "Porcentajes/ prevalencias") was loaded once via the bulk `insert` in `supabase-flashcards.sql` — there is no in-app deck-import UI, new decks are added the same one-off-SQL way.
- Auth is real: Supabase Auth (email+password), using a synthesized fake email `username@ruta-pir.local` since Supabase Auth requires an email-shaped identifier — see `emailDeUsuario`/`usuarioFromSession`/`handleLogin`/`handleSignup` in `App.jsx`. Supabase's Auth dashboard must have "Confirm email" disabled for the Email provider (no real inbox exists for the fake domain, so signup must grant a session immediately). Admin access is still gated by a hardcoded username check against `ADMIN_NAME` ("pabloadmin") — whoever registers that exact username becomes admin and is displayed/stored everywhere as `name: "Pablo"`.
- Backend is Supabase (`src/supabaseClient.js`), used directly from `App.jsx` via `supabase.from(...)` calls, and from `api/generar-preguntas.js` (a separate server-side client, same anon key) to enforce the daily AI-question quota. Tables in use: `preguntas` (questions), `ranking`, `rachas` (streaks + daily-progress + badge totals), `duelos`/`duelo_respuestas` (duel state/answers), `fallos` (per-user per-question fail counts), `favoritos` (per-user saved questions), `ia_uso` (per-user per-day AI generation quota), `flashcards` (shared flashcard deck content), `flashcards_progreso` (per-user SM-2 review state per card). There is no schema/migrations folder in this repo — the schema lives only in Supabase itself; one-off `supabase-*.sql` files at the repo root are migrations already handed to and run by the user, kept only as a record.
- UI preferences (font-size "zoom" scale and page background color, set from the gear icon in the header) are per-device, persisted to `localStorage` under `pir-ajustes` — not synced through Supabase.

### Things to be aware of

- `Src/Main.jsx` (capital `S`) is a stray duplicate of `src/main.jsx`. The actual entry point used by `index.html` is `src/main.jsx` (lowercase); `Src/` is not referenced anywhere and is effectively dead.
- `academia-pir.tsx` at the repo root is an earlier standalone prototype of the app (with its own seeded question data) and is not imported or built — treat it as a legacy reference, not live code.
- `src/supabaseClient.js` has the Supabase URL and anon key hardcoded inline rather than read from environment variables.
