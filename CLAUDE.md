# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start the Vite dev server
- `npm run build` — production build
- `npm run preview` — preview a production build locally

There is no lint or test setup in this repo (no test framework, no ESLint config).

## Architecture

This is a small single-page React app ("AUTOPIR", formerly "Ruta PIR"; repo/package name academia-pir), built with Vite, backed by Supabase.

- Entry chain: `index.html` → `src/main.jsx` → `src/App.jsx`. `src/App.jsx` is the entire application (~2000 lines): all components, view logic, and Supabase calls live in this one file, organized as several feature components rendered by a top-level `AcademiaPIR` component based on a `section` state variable (tab navigation).
- Sections/tabs (`section` state, set via the nav in `AcademiaPIR`; only 4 tabs remain, in this order): `simulacros` (self-test quizzes, labeled "Autoevaluaciones" — see below), `duelo` (1v1 duel/battle mode), `flashcards` (spaced-repetition flashcards, Anki-style, front/back cards seeded from an imported Anki deck — see `flashcards`/`flashcards_progreso` below), `perfil` (last tab: fail history, favorites — kept deliberately light; the daily wheel/"ruleta" used to live here but was relocated into the header, see phase 2 below). There is no `temario` tab — `TEMARIO` (static data in `src/temario.js`) is still imported and used internally to ground AI question generation (`GenerarPreguntasIA`), just not shown as a readable tab. There used to be a `curiosidades` tab (AI-generated trivia, via `api/generar-curiosidades.js`); it was replaced outright by `flashcards` per user request — the `curiosidades`/`curiosidades_vistas` tables and `supabase-curiosidades.sql` are dead but left in Supabase/the repo as history, nothing in `App.jsx` references them anymore.
- `banco` (question bank — "Reales" curated + "Inventadas por IA" AI-generated, open to all users with a daily quota, save-to-bank admin-only; no course/subject filter, just a free-text search box that filters the current tab's questions by substring match against the question/options/explanation/tema) and `ranking` (leaderboard + streaks) are **not** nav tabs — like `Logros` (level/badge grid + streak & accuracy stats), they live behind small icon buttons in the header (`Header`'s `mostrarBanco`/`mostrarRanking` state, next to the pre-existing `mostrarLogros`), positioned award-icon (Logros) → trophy-icon (Ranking) → list-icon (Banco) → gear (Ajustes) → logout. Unlike `Logros`'s small anchored dropdown, clicking the Banco or Ranking icon opens a full-screen overlay (`styles.pantallaCompleta`, `position: fixed; inset: 0`, its own close/`X` button up top) rendering the exact same `<BancoPreguntas>`/`<Ranking>` components and props that used to live in the tabbed `<main>` — the components themselves are unchanged, only their entry point moved from a nav tab to a header-triggered overlay. `Header` now needs the question-bank CRUD callbacks and `rachas` passed down from the root alongside its original `user`/`onLogout`/`miRacha`/`onAjustes` props.
- `PreguntaCard` (the expandable question row inside `BancoPreguntas`) no longer reveals the correct option (and the explanation, which usually gives it away) as soon as a question is expanded — a local `mostrarCorrecta` state (reset to `false` every time the card is expanded/collapsed via `toggleOpen`) gates the correct-answer highlight/checkmark and the explanation text behind a "Ver respuesta correcta" button rendered under the options list; pressing it reveals both instantly. This only applies to `PreguntaCard` — the equivalent review UIs in `Simulacros`' post-quiz screen and `MiPerfil`'s fail history still reveal the correct answer immediately, since those are reviewing an already-answered question rather than browsing the raw bank.
- `Simulacros` ("Autoevaluaciones"): the course/subject picker is labeled "Exámenes" and only lists `curso` values that look like an exam edition (matched via the module-level `esExamen(curso)` helper, a `/^pir\b/i` regex — e.g. "PIR 18", "PIR 20", "PIR 21"…"PIR 25"); the near-empty leftover subject-labeled `curso` values (e.g. "Psicopatología") are filtered out of this specific dropdown, though "Todos" still aggregates everything in the current `incluirInventadas`-scoped pool as before. The dropdown's exam options are sorted newest-first by the number in the label (e.g. PIR 26, 25, 24…), not by insertion/appearance order — extracted with a plain `/\d+/` match on the `curso` string. "Modo relámpago" was redesigned from its original fixed 5-question/60-second countdown into an unlimited streak mode: `startRelampago` shuffles every real (non-`inventada`) question across all exam-labeled cursos (`esExamen`) into the pool, questions are answered one at a time (elapsed time just ticks up for display, no time limit), and the round ends the instant an answer is wrong (`"Racha terminada"`) or the moment the whole shuffled pool has been answered correctly (`"¡Racha perfecta!"`) — there's no repeat-of-failures round like the regular mode. Each new relámpago run reshuffles from scratch (no memory of what was seen in past runs, so repeats before exhausting the pool are expected and intended). Only modo relámpago's result is submitted anywhere: `onStreakAnswer` (which drives `rachas.racha_actual`/`racha_record`, shown as the "Autoevaluaciones" columns on the Ranking tab) and `onFinish`/`submitScore` (insert into the `ranking` table — currently otherwise unused for display) are now gated to `relampago === true`; regular course-based autoevaluaciones no longer touch either, to keep that ranking driven by one well-defined game mode. `onProgresoDiario` (weekly league + daily-wheel eligibility) and `onFallo` (fail history in Perfil) are unaffected and still fire for both modes — including relámpago's own failed question, which still lands in Perfil's fail history like any other. A small persistent `rachaViva` counter (reset to 0 in `startRelampago`, incremented on every correct answer while `relampago`) sits top-right of the run header next to the timer, as a `Flame` icon + number; the flame renders dim/grey ("apagada") while `rachaViva <= recordPrevio` (`miRacha.racha_record`, passed down as a prop from the root) and switches to a lit, glowing orange state the moment the live streak exceeds that prior personal record.
- The `curso` column on `preguntas` is a free-text field, not a fixed taxonomy — for a chunk of imported real questions it actually holds an exam/simulacro label (e.g. "Simulacro 01 (AMIR)") rather than a subject name; those get renamed to their real "PIR YY" edition label via one-off `update` statements in `supabase-*.sql` files as the user requests each renaming (see `supabase-rename-simulacros.sql` for the pattern: a regex anchored on the simulacro number to avoid collisions like "1" matching "10"). Besides renamed simulacros, whole past exams have also been transcribed from PDF and `insert`ed directly with `curso` set to their edition label: `supabase-pir20-preguntas.sql` (198 questions, curso="PIR 20", from an APIR "Simulacro 5" practice-exam PDF; 12 annulled questions from the source were skipped; includes real `explicacion`/`tema` per question) and `supabase-pir18-preguntas.sql` (235 questions, curso="PIR 18", from the official 2018 PIR exam PDF cross-checked against the Ministerio de Sanidad's official answer key; no explanations exist for this source, so `tema` is a placeholder "Pregunta N" and `explicacion` is null). Both were run by the user directly in the Supabase SQL editor.
- `Flashcards`: front/back cards (`flashcards.frontal`/`.posterior`, grouped by `mazo`) reviewed with a simplified SM-2 spaced-repetition algorithm (`calcularSM2` in `App.jsx`, same model Anki uses) — a card is "due" when `flashcards_progreso.proxima_revision` is null or `<=` today. Each review ends with one of 4 difficulty ratings (Muy difícil/Difícil/Fácil/Muy fácil, mapped to SM-2 quality 0/3/4/5) which updates that user's `ease_factor`, `intervalo_dias`, `repeticiones` and `proxima_revision` for that card via `registrarRepasoFlashcard`. Before starting, the user picks how many due cards to do that round (`numTarjetas`, defaulting to `TAM_SESION_FLASHCARDS` = 20, same raw-while-typing/clamp-on-blur input pattern as `Simulacros`' cantidad field); `ordenarPorPrioridad` then orders the due pool so cards just reset by a "Muy difícil" rating (`repeticiones === 0`) come first, other due reviews next (most overdue first), and never-seen cards last, before slicing to the chosen count — so the ordering itself reacts to the difficulty feedback already given, not just the next-due-date. The deck data itself (271 cards from a "Mi baraja" Anki export, tagged "Porcentajes/ prevalencias") was loaded once via the bulk `insert` in `supabase-flashcards.sql`; there is no in-app deck-import UI, new decks are added the same one-off-SQL way. A collapsible "Ver y editar tarjetas" section (search box + `FlashcardEditableCard` list, boxed/expandable like `PreguntaCard` in Banco de preguntas) lets anyone browse the full deck; only `user.isAdmin` sees the inline edit form (`onUpdate` → `updateFlashcard`, `supabase.from("flashcards").update(...)`) — there's no delete/add-card UI yet, only edit.
- Auth is real: Supabase Auth (email+password), using a synthesized fake email `username@ruta-pir.local` since Supabase Auth requires an email-shaped identifier — see `emailDeUsuario`/`usuarioFromSession`/`handleLogin`/`handleSignup` in `App.jsx`. Supabase's Auth dashboard must have "Confirm email" disabled for the Email provider (no real inbox exists for the fake domain, so signup must grant a session immediately). Admin access is still gated by a hardcoded username check against `ADMIN_NAME` ("pabloadmin") — whoever registers that exact username becomes admin and is displayed/stored everywhere as `name: "Pablo"`.
- Backend is Supabase (`src/supabaseClient.js`), used directly from `App.jsx` via `supabase.from(...)` calls, and from `api/generar-preguntas.js` (a separate server-side client, same anon key) to enforce the daily AI-question quota. Tables in use: `preguntas` (questions), `ranking`, `rachas` (streaks + daily-progress + badge totals), `duelos`/`duelo_respuestas` (duel state/answers), `fallos` (per-user per-question fail counts), `favoritos` (per-user saved questions), `ia_uso` (per-user per-day AI generation quota), `flashcards` (shared flashcard deck content), `flashcards_progreso` (per-user SM-2 review state per card). There is no schema/migrations folder in this repo — the schema lives only in Supabase itself; one-off `supabase-*.sql` files at the repo root are migrations already handed to and run by the user, kept only as a record.
- UI preferences (font-size "zoom" scale, page background color, and — as of the visual redesign below — a typography choice, all set from the gear icon in the header) are per-device, persisted to `localStorage` under `pir-ajustes` — not synced through Supabase.
- **Visual redesign, phase 1 ("cuaderno de examen"):** the app is mid-migration from its original navy/teal SaaS look to a new editorial identity worked out first as standalone HTML mockups (Artifacts, not part of this repo) before being ported into `App.jsx`. Design tokens live as top-level `const`s right above `AJUSTES_DEFECTO` (`TINTA`/`TINTA_SUAVE`/`TINTA_TENUE` ink, `RAYA`/`RAYA_FUERTE` hairline borders, `ACENTO`/`ACENTO_SUAVE` — a brick red, the brand/chrome/wrong-answer color, replacing the old teal `#2E7D6B` for anything that isn't a correctness signal, `CORRECTO`/`CORRECTO_SUAVE` — green, reserved strictly for correct-answer/success states, `ORO` for streak/badge accents) plus `SOMBRA_SUAVE` (shared card shadow) declared just above the `styles` object. Display typography (Fraunces by default) is threaded through via a CSS custom property, not props: the root app `<div>` sets `"--font-display"` inline from `ajustes.fuente`/`FUENTES`, and every serif/heading spot in `styles` (and a few inline JSX styles) reads `fontFamily: "var(--font-display)"` so switching fonts in Ajustes re-themes the whole tree with no prop drilling. `FUENTES` (Fraunces / Source Serif 4 "Clásica" / IBM Plex Sans "Solo sans") is a new `AjustesPanel` control alongside the existing size/color ones, stored as `ajustes.fuente`. `COLORES_FONDO` was reworked to the new light paper tones (dark/near-black tones were deliberately left out of this simple flat-background-swap mechanism, since ink colors don't flip with it). Fonts (Fraunces, Source Serif 4, IBM Plex Sans, IBM Plex Mono) load via a Google Fonts `<link>` in `index.html`. Phase 1 covers global chrome (`Header`, `Nav`), the shared primitives used everywhere (`Card`, `SectionTitle`, `FieldLabel`, buttons), and the `Simulacros` question/options UI (rounded bordered options, red/green reveal states). `Flashcards`, `MiPerfil`, `Duelo`, `BancoPreguntas`/`Ranking` still only inherit the shared-primitive restyle and haven't had their own layouts reworked yet — that's the next phase.
- **Visual redesign, phase 2 (Flashcards + Perfil):** added two more design tokens alongside `ACENTO`/`CORRECTO`/`ORO` — `AVISO`/`AVISO_SUAVE` (orange) and `CAUTELA`/`CAUTELA_SUAVE` (yellow) — so `CALIFICACIONES_FLASHCARD`'s 4 difficulty ratings now map to a red→orange→yellow→green scale (`ACENTO`→`AVISO`→`CAUTELA`→`CORRECTO`) instead of hardcoded hex. `Flashcards`' active-review card is now a real CSS 3D flip card (`.flip-container`/`.flip-inner`/`.flip-face`, `perspective`/`rotateY(180deg)`/`backface-visibility: hidden`, injected via a `<style>` tag following the same keyframe-injection pattern already used in `Simulacros`) instead of the old "reveal text below a dashed line" behavior — tapping the card toggles `revelada` and flips it either direction (front→back or back→front), so there's no separate "Ver respuesta"/"Ver pregunta" button anymore, just a small "Toca la tarjeta para ver la respuesta" hint before the first flip; the SM-2 difficulty-rating buttons still only appear once `revelada` is true. `Card` now forwards an optional `className` prop (needed so the flip faces can be styled via CSS classes rather than inline `style`). In `MiPerfil`, "Historial de fallos" no longer uses the generic `<PreguntasPlegables>` (which reveals the correct answer immediately on expand); it now renders a `<FalloRepetible>` per fallo, which shows the question and "fallada N veces" without revealing the answer, and only offers a "Repetir" button that expands an inline mini-quiz (reusing the `daypoOpcion`/`daypoOpcionCorrecta`/`daypoOpcionIncorrecta` styles, red/green immediate feedback on picking an option, plus a "Repetir de nuevo" reset) — per user request, the question is never removed from the fail-history list regardless of whether the retry is answered correctly. The daily wheel (`RuletaDiaria`, itself unchanged) was relocated out of `MiPerfil` into a new `Header` icon button (`Sparkles` icon, between the Banco and Ajustes icons) that opens the same small anchored-dropdown pattern `Logros` uses; `Header` gained an `onGirarRuleta` prop and local `mostrarRuleta` state for this. "Favoritas" in `MiPerfil` is unaffected and still uses `<PreguntasPlegables>` (revealing the answer immediately is intended there, since it's reviewing an already-known question rather than a fresh retry).
- `Header` also has a "Frase motivadora" icon (`Lightbulb`, next to Ajustes) backed by a module-level `FRASES_MOTIVADORAS` array (~24 hardcoded Spanish phrases grounded in the app's own features — autoevaluaciones, flashcards, duelo, rachas — not generic motivational-poster copy). Clicking the icon itself (not just the "Otra frase" link inside the popover) always rerolls to a new phrase different from the one showing and opens the dropdown; this is local `Header` state (`frase`/`mostrarFrase`), not persisted anywhere. The phrase itself is deliberately rendered large and in italic Fraunces (hardcoded, independent of the user's `ajustes.fuente` choice) for a "poem-like" weight, rather than the smaller body-text styling used elsewhere in the dropdown.
- **`AuthScreen` (login/signup screen) has its own, deliberately separate visual identity ("sala de examen"), distinct from the "cuaderno de examen" look used everywhere past login:** a dark card (`PORTADA_TARJETA = "#1C170F"`), gold accents (`PORTADA_DORADO = "#E9C878"`) for the active tab and submit button — all worked out first as standalone HTML mockups (an Artifact, not part of this repo) with several selectable directions and a live color-swatch picker before one was chosen and ported in, then refined further directly in `App.jsx` against a reference screenshot the user liked. The old circular `Compass` icon mark above the wordmark is gone. `FondoPortada` (brought back after a brief flat-matte-color detour, redesigned) fills the whole screen with 4 large soft blurred radial-gradient "blooms" (gold/brick-red/green, all at low opacity, `filter: blur(60px)`, rotated, positioned off the four corners) over a near-white base — a flowing gradient look modeled on a reference screenshot the user shared, using the app's own brand hues instead of the reference's generic blue/purple/pink so it still reads as AUTOPIR. `WordmarkPortada` (a small dedicated component, reused only here) went through two more iterations after that: it briefly sat on its own solid dark plaque (a rotated rounded rectangle behind the letters, like a nameplate) with flat gold letters, but the user asked for that "sticker" to be removed too, plus a typeface change — so it's now bare text again (no background box, no rotation), set in `'Big Shoulders Display'` (a bold condensed display face loaded via the same Google Fonts `<link>` in `index.html`, weight 800, `color: TINTA`) instead of the earlier Fraunces-based treatment, at a much larger responsive size (`clamp(48px, 10vw, 76px)`) — deliberately NOT read through `var(--font-display)`/`ajustes.fuente` like the rest of the app, since this wordmark's typeface is independent of the user's font preference. It splits its `texto` prop into per-letter `<span>`s that drop in with a staggered, bouncy fall-and-impact CSS animation (`portadaCaer`/`portadaGolpe` keyframes, injected via a `<style>` tag in the same per-component pattern used elsewhere, e.g. `Simulacros`' `.acierto-anim`) — each letter also flashes a brief radial gold "impact" glow underneath it on landing; per-letter fall rotation is randomized once via `useMemo` (keyed on `texto`) rather than on every render, so retyping the login form doesn't jitter it. The card, its two/three inputs, and the submit button were all also deliberately sized up (bigger padding/font-size, `authCard` gets `padding: 34`, the container's `maxWidth` went from 340 to 480) so the whole login screen takes up noticeably more of the viewport, per explicit user request ("que ocupe más pantalla"). The submit button is wrapped in a slow (7s), low-opacity rotating conic-gradient "light chasing the border" effect (`.portada-btn-glow`, a real absolutely-positioned sibling div rather than a `::before`, since this is plain inline-styled React) — deliberately subtle and only on this one button; the username/password inputs do NOT have this animation (an earlier iteration had it on all three and it was reverted as "too much"). The login tab reads "Iniciar sesión" rather than "Entrar" specifically so it no longer duplicates the submit button's own "Entrar" label. All of this is local to `AuthScreen`/`WordmarkPortada`/`FondoPortada` — it does not touch `TINTA`/`ACENTO`/the shared `styles` object's `tabOrigenBtn`/`authCard`/etc. (those stay exactly as used by `BancoPreguntas`'s Reales/Inventadas toggle and elsewhere), it only overrides them inline per-instance. (Also: mixing the `border` shorthand from a spread base style with a `borderColor`-only override on the same element trips a React dev warning about shorthand/longhand conflicts on re-render — worth remembering if this screen's styling is touched again — so these overrides always redeclare the full `border` shorthand instead.)

### Things to be aware of

- `Src/Main.jsx` (capital `S`) is a stray duplicate of `src/main.jsx`. The actual entry point used by `index.html` is `src/main.jsx` (lowercase); `Src/` is not referenced anywhere and is effectively dead.
- `academia-pir.tsx` at the repo root is an earlier standalone prototype of the app (with its own seeded question data) and is not imported or built — treat it as a legacy reference, not live code.
- `src/supabaseClient.js` has the Supabase URL and anon key hardcoded inline rather than read from environment variables.
